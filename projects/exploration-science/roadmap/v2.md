# V2 v0 — scène Starlink de qualité illustration premium

Validée par l'utilisateur le 2026-10-19 (session 1 de la V2, planification).

## Principe directeur

- **Contrat d'acceptation : `QUALITY_BAR.md`.** Une étape n'est cochée que sur captures réelles du
  navigateur, inspectées, avec la grille visuelle remplie. Compiler n'est pas livrer.
- **Aucune API externe** de génération (3D, image, texture) ni de rendu. Tout asset est produit par
  script Blender (`bpy` 5.2.2 épinglé), dans le dépôt, de façon reproductible, par commande.
- **Style** : illustration isométrique éditoriale, épurée, industrielle ; diorama sur socle coupé,
  fond discret ; caméra perspective à focale longue (~20°). `docs/v2-reference-starlink.png` reste
  une référence de contenu et d'ambiance, pas de style.
- **Pile** (décision validée, dérogation explicite au « pas de framework UI » du `CLAUDE.md` projet) :
  React + React Three Fiber + drei, entrée `v2.html` dans le même projet Vite. Le prototype Phase 0
  (`index.html`, `engine/`) reste intact et déployé. Réutilisés : simulateurs
  (`engine/src/plugins/simulators/`), validation Ajv/JSON Schema, textes séparés par langue.
- **Rendu** : AO et ombres de contact précalculées par Cycles (CPU) dans les couleurs de sommet,
  aucune texture ; une lumière directionnelle temps réel, ombre douce au sol seulement ; palette
  unique `art/palette.json` partagée par Blender et l'app ; carte d'environnement locale
  (RoomEnvironment) pour métal et verre.
- **On refuse** : un monde vaste avant une scène aboutie ; une simplification silencieuse quand la
  qualité résiste (on explique le compromis et on propose une alternative, QUALITY_BAR §9).
- Ordre : outillage → données → scène de référence statique (QUALITY_BAR §8, priorités 1 à 3) →
  connexions et narration (4) → navigation (5) → performances (6).

## Mesures communes

Captures (`npm run capture`, Playwright/Chromium, facteur de pixels 2) en 4 formats : 1366×1024,
1024×1366, 390×844, 1920×1080. Jeu de captures : vue globale, rapprochée de chacun des 4 objets,
détail de l'antenne, fiche ouverte, étapes de visite système puis objet, flux à mi-animation,
feuille de silhouettes. Publiées dans une page de revue à chaque itération, avec défauts relevés.

Grille visuelle (QUALITY_BAR §6) : direction artistique cohérente · 4 objets reconnaissables sans
libellé · volume par matériaux, lumière, ombres · composition qui montre les relations · aucun
défaut majeur · pas un assemblage de primitives · panneaux sans masquer l'essentiel. Chacun
« tenu / pas tenu » + capture qui le prouve.

Budgets : modèles ≤ 5 Mo au total · triangles visibles ≤ 300 k · appels de dessin ≤ 80 ·
recouvrement panneaux / objets principaux ≤ 10 % · contraste objet / couronne ≥ 3:1 · palette
≤ 6 neutres + ≤ 3 accents · iPad Safari (mesuré par l'utilisateur) ≥ 55 i/s médian, aucun
plantage sur 20 allers-retours. Chromium sans GPU (SwiftShader) ne mesure pas la fluidité.

1. **Système** `content/v2/systems/starlink-home.json` — ce qui existe et comment c'est relié.
   ```json
   { "formatVersion": "v2-0.1", "id": "starlink-home", "titleKey": "system.title",
     "objects": [
       { "id": "house",     "role": "main",    "placement": { "on": "island", "position": [-2, 0, 1], "rotationZDeg": 20 } },
       { "id": "terminal",  "role": "main",    "placement": { "on": "house",  "anchor": "roof" }, "representations": ["envelope", "detail"] },
       { "id": "satellite", "role": "main",    "placement": { "airborne": true, "position": [0, 0, 9] } },
       { "id": "ground-station", "role": "main", "placement": { "on": "island", "position": [3, 0, -2] } },
       { "id": "island",    "role": "setting" },
       { "id": "pine-01",   "role": "decor",   "placement": { "on": "island", "position": [1, 0, 2] } } ],
     "connections": [
       { "id": "uplink",   "from": "terminal#beam",        "to": "satellite#antenna",   "kind": "radio" },
       { "id": "feeder",   "from": "satellite#antenna",    "to": "ground-station#dish", "kind": "radio" },
       { "id": "backhaul", "from": "ground-station#fibre", "to": "internet#pop",        "kind": "fibre" } ],
     "flows": [ { "id": "data-down", "path": ["backhaul", "feeder", "uplink"], "direction": "reverse" } ] }
   ```
   `role` : `main` = sélectionnable avec fiche, `setting` = socle, `decor` = non sélectionnable.
   `#beam`, `#roof` = points d'attache nommés (empties exportés dans le GLB). Blender lit les
   positions ici : plus de double saisie.
2. **Modèles** `art/assets.json` — id → script Blender et paramètres par représentation
   (`"terminal": { "envelope": "assets.terminal", "detail": "assets.terminal_exploded" }`).
3. **Rendu et caméra** `content/v2/render.json` — lumières, environnement, styles de liaison par
   `kind` (radio : faisceau pointillé bleu ; fibre : trait au sol), plans cadrés par une liste
   d'objets plutôt que par une position fixe (tient en portrait comme en paysage) :
   `"global": { "fit": ["house", "satellite", "ground-station"], "azimuthDeg": -35, "elevationDeg": 32 }`,
   plus `object:<id>` et `detail:<id>`, limites d'orbite et de zoom.
4. **Visite** `content/v2/tours/starlink-home.json` — étapes
   `{ id, shot, focus: {kind:"system"} | {kind:"object", id}, highlight, flows, textKey }`. Validation
   de la règle de récit : 1re étape = système ; un objet n'est sujet d'une étape qu'après une étape
   système qui l'a mis en évidence (`highlight`).
5. **Textes** `content/v2/texts.fr.json` — fiches par objet (titre, une phrase, 2 à 4 chiffres reliés
   à `sources.json`, format de la Phase 0) et sous-titres de visite.
